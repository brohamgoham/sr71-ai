# Phase 0–1 implementation plan

Status: draft; implementation has not started.
Specs: [original foundation](../specs/2026-09-06-phases-0-3-design.md),
[product/contract revision](../specs/2026-09-06-product-and-contract-revision.md),
[runtime schema](../specs/2026-09-06-v1-runtime-design.md).
The revised ABI and world schema take precedence over original sketches.

## Build discipline

Read repository instructions and relevant installed skills. Work on a feature branch;
do not discard the currently untracked repository files. No commits to main.
Record real tool versions and check outcomes in the handoff as work completes.
Each numbered task below is one reviewable change or setup step. Do not mark an
external step complete from a mock or leave a failing check described as passed.

Do not install or configure anything during specification review. When building,
toolchain setup precedes Move code. Use actual installed CLI help for syntax and
the installed sui-install/sui-client skills for network-specific setup.

## 0.1 Establish toolchains and testnet treasury

1. Update Sui for testnet using `suiup update sui@testnet`, then
   `suiup switch sui@testnet`; verify actual active version. If the installed suiup
   surface differs, inspect its help and record the equivalent testnet operation.
   Updating the download alone does not prove the active binary changed.
2. Configure `sui client` explicitly for testnet. Reuse a suitable treasury alias
   if present; otherwise create one Ed25519 address. Verify network and public
   address. Keep generated secrets and recovery output out of logs and the repo.
3. Obtain testnet faucet funding through a currently supported route. Do not assume
   the installed CLI faucet command supports testnet. Confirm balance on testnet;
   document a faucet blockage rather than fabricating a funded state.
4. Pin a concrete current Rust stable release in rust-toolchain.toml with rustfmt
   and clippy. Verify the chosen dependencies' MSRV. Install prek and cargo-deny if
   missing, within available permissions. Record tool versions.

Evidence: Sui version, testnet identity, public treasury alias/address and confirmed
balance. Phase 0 needs working gas funds, not the entire default-world bankroll.

## 0.2 Workspace and policy

Files: root Cargo.toml, Cargo.lock, rust-toolchain.toml, deny.toml,
clippy.toml, .pre-commit-config.yaml, .gitignore; crates/world/Cargo.toml.

Replace the hello-world package with resolver 3 workspace and inherited lints.
Read any actual global lint standards before claiming to copy them. At minimum
enforce repository requirements: denied unwrap, warned expect, clippy warnings as
errors, function length/parameter/line limits, thiserror libraries, anyhow binaries,
tracing output and exhaustive project enums. Do not weaken checks to pass.

Create only compilable phase-owned targets. World is real in Phase 0; later crate
directories may be documented without inventing functionality. If empty targets
are retained, they contain no speculative APIs. Workspace dependencies pin exact
compatible published versions, checked against crates.io at implementation time;
the original draft's version table is historical guidance, not a lockfile.

Use deny for advisories, license review and source restrictions. Allow only actual
reviewed dependency licenses; do not broadly exempt all Sui crates. Hooks run fmt,
clippy with all targets/features and warnings denied, and Move tests from the package
directory. `prek install` is a local setup step, not something file creation proves.
Ignore runtime secrets, runs, local config, .env and generated build outputs while
retaining deploy metadata, lockfiles, worlds and intentionally sanitized reports.

## 0.3 Exact amounts and configuration types

Files: crates/world/src/{lib.rs,amount.rs,config.rs,error.rs} and tests.
Public domain types expose validated values through small read-only APIs.
Implement Mist decimal parsing with checked u64 arithmetic and no float intermediate.
Use a TOML representation that retains numeric lexical text; prove 0.1, one mist,
u64 limits and excessive precision before selecting the parser path. If the chosen
toml deserializer loses decimal text, use its document representation or a compatible
lexical parser; do not recover it by formatting an f64. Record chosen crates in plan.

Test integer and decimal inputs, quoted exact amounts, nine/tenth fractional digits,
negative/zero floor, exponents, overflow, invalid types and errors with field paths.
Add independent errors/tests for file read, TOML syntax, missing/unknown fields,
class rules, roster sum, duration/epoch bounds, provider, bracket, agent overrides,
name/disposition bounds and all new agent settings. Validate total starting-wealth
and worst-case floor arithmetic. Do not expand a huge count before checking limits.

## 0.4 Roster and authored worlds

Files: crates/world/src/roster.rs, worlds/default.toml,
worlds/design-session.toml, crates/world/src/main.rs, tests.

Specify and freeze roster algorithm v1: class order then within-class index; select
unique default names from a fixed >=64-name list using a documented seeded shuffle;
apply index overrides; validate final name uniqueness. Use a pinned reproducible
algorithm rather than platform-dependent hashes. Wallet keys are outside this module.

Default world uses all 16 names/dispositions and factual class birth text in the
product spec; design-session world preserves original class prompts. Render class
balance placeholders from validated values; reject unknown placeholders. Materialize
defaults and preserve input bytes in later run manifests. Implement `World::load`,
in-memory parse for tests, `World::agents`, bracket classification and validation CLI.

Test a golden roster for seed 7, deterministic repetition, unique 64-agent expansion,
override validation, distinct seeds over fixed fixtures, class counts and birth text.
Default world round-trip verifies semantic equality without rounding amounts or
losing prompts. The roster CLI uses tracing and returns nonzero on bad config.

## 0.5 Empty Move package and scaffold exit

Use sui-move-project and sui-build skills. Create contracts/square with current
Move.toml, edition 2024 and automatic framework resolution. Build the empty package;
do not write the Phase 1 functions yet. Run from contracts/square.

Required exit checks:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
cargo deny check
cargo run -p world -- worlds/default.toml
```

Also `sui move build` in contracts/square, a malformed-world CLI case with the right
field in its error, and hook installation/execution evidence. Resolve dependency
advisories or report a real blocker. No live model is needed.

## 5A. Build the viewing prototype before the contract

Follow [Phase 5A](../specs/2026-09-06-phases-5-6-design.md). Implement the pure
observer reducer, fixture reader, watch/cast/economy layouts, follow and replay in
crates/tui. Author DEMO fixtures with chain-shaped events from the revised schema;
fixture source is permanently labeled. No chain or model connection is required.

Validate layouts, keyboard flow and quiet/burst/failure states. Present the runnable
prototype to the owner for feedback. Record that feedback separately from automated
checks. Adjust the view while changes are cheap. Do not silently mark enjoyment
validated if the owner has not tried it.

## 1.1 Objects, capabilities and run creation

Files: contracts/square/sources/square.move, tests/square_tests.move.
Read modern-move-syntax, sui-move, naming-conventions, composable-move-functions,
move-security and move-unit-testing before writing code.

Implement Square, Agent, bound AdminCap, create, init, Created and read-only getters.
Object-first/cap-second parameter order supersedes the original table. Public create
returns the cap, while init transfers it to the publisher. Test two separate Squares,
shared ownership, cap matching, Created fields and every getter. No public mutators
for identity or origin. Keep state helpers small and specific.

## 1.2 Registration and epoch

Implement register and tick, exact revised errors and events. Verify correct cap,
capacity, unique address/name and UTF-8 bounds before mutation. Test all failure paths,
64-agent boundary, independent Square epochs and matching event Square IDs. Missing
agent read must use ENotRegistered. Do not expose cap-free privileged helpers.

## 1.3 Posts, replies and gifts

Implement post with reply sequence/addressee validation; give consumes an owned
Coin<SUI>, transfers to the validated recipient and updates counters. Giving all
wealth is permitted; no moral checks or floor reserve enforced on sender spending.
Test exact boundary sizes, reply sequence, nonregistration, zero/self gifts, totals,
recipient coin ownership, origin preservation and all event payloads. Composite
post+give PTBs must roll back together if either action fails.

Where failure is in a framework module, assert expected abort location as well as
code. Test insufficient split at the transaction boundary; never imply give itself
constructs unavailable funds. Run all Move tests and build with compiler warnings
reviewed. Re-run workspace checks for changed Rust fixture/schema code.

## 1.4 Publish and capture evidence

Confirm testnet identity and treasury publicly before publishing. Publish the reviewed
package; record package ID, initial Square and matching AdminCap, initial shared
version, checkpoint and digest in worlds/testnet.toml. Do not commit any private key.

Register treasury in the disposable initial Square and post using a CLI PTB. Verify
Posted event in effects and a testnet explorer. Create a second empty Square with
create, transferring its returned cap to treasury, to prove fresh runs need no new
publish. Never reuse the populated smoke Square for the sixteen-agent experiment.

Capture BCS for all five event types in fixtures with source digest, package, Square,
checkpoint and ABI hash for Phase 2. Capture gift/reply events with appropriate test
addresses, not mock bytes labeled as real. Record exact commands and public results
in handoff. Publishing is complete only when confirmed on testnet.
