# Phase 2–6 implementation sequence

Status: v1 specifications approved by the owner; Phase 5A prototype implemented.
Live phases remain pending. Future murder mechanics have no implementation approval.
Build order: 0 → 5A prototype → 1 → 2 → 3 → 4 → 5B → 6.
The [Phase 0–1 plan](2026-09-06-phases-0-1-plan.md) includes the early prototype.

## Phase 2: prove the chain boundaries before hiding them

Spec: [runtime contract](../specs/2026-09-06-v1-runtime-design.md).
Crate: chain; modules config, signer, deploy, reads, events, transaction, run.

1. **Compatibility spike.** Pin compatible modular Rust Sui crates; prove testnet
   chain identity, Square/Table reads, paginated coin selection, post+give PTB and
   one/two-signature submissions. Compile actual methods, never SDK-like sketches.
   Record the installed RPC methods/field masks and actual testnet responses.
2. **History spike.** Prove filtered List/Subscribe and watermark recovery using
   the selected endpoint, or select complete checkpoint ingestion with local
   filtering. Include a deliberate disconnect and overlapping backfill. Identify
   retention behavior and explicitly fail an unavailable-history request.
3. **Gas spike.** Test sponsored address-balance gas with concurrent requests,
   expiration and accounting. If any required behavior is unavailable, select the
   specified 32-coin pool and verify exclusive leases. Write the decision and
   minimal reproducer results into this plan before the admin depends on it.
4. **Typed implementation.** Implement chain's public project contracts and safe
   errors. Include create/run deployment, all five events, Table reconstruction,
   exact amounts, merge/split coin selection and changed-gas/kind verification.
5. **Recovery.** Implement follow, transaction lookup and explicit unknown results.
   Build tests with real captured BCS plus simulated transport failures. Never
   conflate not-found, failed execution, lost response and confirmed success.
6. **Exit.** Ignored testnet binary posts and gives as a fresh sender with treasury
   gas, verifies exact recipient amount, unchanged sender gas burden and recovered
   events. All offline checks pass with no testnet connection.

Each capability spike has a finite result: demonstrated path plus evidence, or a
documented incompatibility that stops dependent implementation. Do not keep building
on a guessed API. Network approval constraints are reported separately from code bugs.

## Phase 3: administration that can restart safely

Spec: [runtime contract](../specs/2026-09-06-v1-runtime-design.md).
Crate: admin; modules config, prepare, lifecycle, journal, sponsor, gas, epochs.

1. Implement private operator config, testnet identity gate, funds calculation,
   exclusive writer locks, durable append and atomic state updates. Test partial
   trailing writes, interior corruption, disk-full and permission failures.
2. Implement manifest/world freezing, cryptographic key creation, fresh Square
   creation with matching cap, funding and registration batch journals. Recovery
   reuses identities and checks chain outcomes before repeating a batch.
3. Implement lifecycle/round transitions, exact opening top-ups and closing
   snapshots. Keep `SquareEpoch` distinct from network epoch. Test cooldown/turn
   admissions, slow guaranteed turns, no optional-reaction carryover and stop/resume.
4. Implement loopback auth and the four specified routes. Validate turn-start and
   template-based sponsorship independently of model output. Persist signatures
   and leases before return; duplicate operation IDs are idempotent.
5. Implement chosen gas strategy, simulation/caps, quarantined pending leases and
   reconciliation. Prove that a timeout followed by success cannot reuse gas
   unsafely or duplicate funding, a tick, top-up or gift.
6. Run the ignored three-epoch drain test. Evidence includes initial balances,
   top-up differences, confirmed transactions, accounting equality and restart
   during an in-flight operation. Inspect new-run isolation in two Squares.

Gate: complete crash/failure tests, exact verified top-ups, no runtime keys in logs
or tracked artifacts, no chain writes outside testnet, no LLM implementation yet.

## Phase 4: residents with continuity

Spec: [agents](../specs/2026-09-06-phase-4-agents-design.md).
Crate: agents; modules config, provider, prompt, tools, memory, journal, scheduler.

1. Compile the Rig adapter compatibility test: real supported macro, typed schemas,
   captured mock-model output and mock errors; verify the direct rig-core package
   exports rather than assuming facade documentation names. Pin the tested path.
2. Implement validated birth prompts and complete-roster observation builder.
   Add source-event pinning for durable beliefs and bounded memory. Test no private
   cross-agent leakage and exact observation archives before calling providers.
3. Implement the three proposal tools and full-bundle validation; no tool closure
   signs directly. Test all valid bundles, exact money parsing, invalid targets,
   oversized output and malicious requests. Compose one atomic post+gift PTB.
4. Implement base/reactive scheduling, fair queues, coalescing, cooldown and per-agent
   exclusion. Use fake time and scripted mock responses to prove bounds and recovery.
   A simulated burst must not exceed `population * max_turns_per_epoch` admitted turns.
5. Integrate sponsor verification, agent signing, journals and digest recovery.
   Crash tests prove one confirmed effect per logical action and no duplicate model
   decision after Proposed was persisted. A lost pre-Proposed completion may repeat
   provider cost, recorded explicitly.
6. Implement run preflight for the owner's actual provider/model. Offline tests use
   Rig mocks exclusively. Live two-agent API/testnet smoke is explicitly launched,
   with no model substitution and public evidence for actions plus usage records.

Gate: sixteen agents can use the loop, wait and recover; technical gift support is
proven separately. No minimum number of voluntary gifts, no prompt repair for drama.

## Phase 5B: turn the prototype into the live viewer

Spec: [observer and experiment](../specs/2026-09-06-phases-5-6-design.md).
Crate: tui. Keep its existing fixture reducer and terminal view.

1. Add chain/runtime adapters with explicit provenance and independent freshness.
   Ensure pending actions cannot change confirmed balances or counters.
2. Implement deterministic moments, pair summaries, reply grouping and evidence
   navigation. Validate event/source IDs; do not infer motives as facts.
3. Wire pause-view, catch-up and archived replay using the same reducer. Seeking
   must not reveal future notes or events. Test burst/backpressure without event loss.
4. Implement economy calculations with integer arithmetic, verified top-ups and
   external-flow detection. Test all-equal, all-zero, one-whale and missing-data cases.
5. Complete accessible sizes, no-color/reduced-motion, sanitization and terminal
   restoration. Run without keystore read permissions; exiting must not stop admin.
6. Show the owner a real live run and offline replay. Record actual feedback; revise
   pacing and hierarchy without changing simulation behavior to improve the display.

Gate: offline replay and live events agree at the same cut; no confirmed fiction,
responsive input, correct balances, and recorded owner review of the experience.

## Phase 6: run, archive, evaluate

1. Implement headless `tui report` using the same pure observer projection. Define
   an allowlist of archive files; exclude keys, auth/config secrets and pending signed
   bytes. Test report reproducibility and refusal to overwrite another run.
2. Confirm the selected GPT/API access and provider settings before paid execution.
   Estimate maximum calls as `population * max_turns_per_epoch * epochs`, plus at
   most one permitted transport retry per call. With 16/2/100 this is 3,200 decisions,
   up to 6,400 requests including retries, not a promise that every turn is used.
   Derive estimated cost from current chosen-model prices and measured prompt sizes.
3. Preflight funds and artifacts, smoke two agents, then run the chosen sixteen-agent
   world to declared completion. Record every outage, failed turn and external flow.
4. Generate the sanitized report/archive and open offline replay without network,
   keys or model credentials. Check conservation and completeness against chain evidence.
5. Write a short actual run narrative linked to moments, plus the owner's actual
   viewing feedback. Separate model self-reports, measured outcomes and interpretation.
6. Identify the next experiment by changing a world file. Do not start graphics,
   rent, lotteries or a director model because a first run was quiet.
